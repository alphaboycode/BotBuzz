EXECUTIVE SUMMARY:
BotBuzz is an unstoppable, onchain news publishing and social curation protocol
engineered natively for the BOT blockchain ecosystem. Built with pure Solidity
(^0.8.24) and OpenZeppelin 5.x security primitives, BotBuzz eliminates Web2
gatekeepers, algorithmic newsfeeds, and platform ad-rent seeking.

Every headline and story is preserved directly in smart contract state as plain
UTF-8 strings—free of external storage, IPFS pinning dependencies, or centralized
databases. Readers vote in real time (+1/-1 score) and stream native BOT tips
directly to authors' wallets via gas-optimized, reentrancy-hardened transactions.

SLIDE 2: THE PROBLEM
--------------------------------------------------------------------------------
Current digital media and Web3 content distribution suffer from four critical
structural failures:

1. Algorithmic Gatekeeping & Censorship:
   - Centralized platforms (Twitter/X, Reddit, Medium) censor stories, deplatform
     independent voices, and manipulate discovery algorithms for corporate engagement.

2. Fragile Decentralized Storage:
   - Existing "decentralized" alternatives rely on IPFS gateways, Arweave bundling,
     or external indexing nodes that frequently experience broken gateways, pinning
     expiration, and indexing lag.

3. Broken Creator Monetization:
   - Content creators receive fractions of pennies from ad networks, while payment
     processors and platforms extract 30–50% take rates. There is no frictionless,
     micro-tipping layer embedded directly at the protocol level.

4. Bot Manipulation & Sybil Clickbait:
   - Without economic stakes or cryptographic identity, legacy newsfeeds are inundated
     by synthetic engagement farms and unverified rumor mills.

--------------------------------------------------------------------------------
SLIDE 3: THE SOLUTION - BOTBUZZ
--------------------------------------------------------------------------------
BotBuzz provides an immutable, transparent, and direct publishing primitive:

- 100% Fully Onchain Storage:
  Titles (up to 100 bytes) and descriptions (up to 500 bytes) are permanently
  stored in Solidity smart contract storage. No IPFS, no cloud servers, no downtime.

- Direct Native BOT Micropayments:
  Readers send native BOT tips directly into the author's wallet in the same
  transaction. The contract takes 0% fee, holds 0 BOT, and ensures checks-effects-
  interactions with OpenZeppelin ReentrancyGuard.

- Cryptographic Curation & Transparent Scoring:
  One vote per wallet per post (Like = +1, Dislike = -1). Transparent score calculation
  (`likes - dislikes`) with instant vote switching and counter-balancing removal.

- Zero Protocol Rent-Seeking & No Admin Backdoors:
  No owner, no upgradeability, no paused state, no administrative controls, and
  no content moderation backdoors. The news board belongs entirely to the network.

SLIDE 4: SMART CONTRACT ARCHITECTURE & TECHNICAL INNOVATION
--------------------------------------------------------------------------------
Core Protocol Design (`BotBuzz.sol`):

        [ Reader / Tipper ]                 [ Author Wallet ]
                 |                                  ^
          tip(postId) {msg.value}                   |
                 |                       direct ETH/BOT transfer
                 v                                  |
      +---------------------------------------------+-----+
      |                       BotBuzz                     |
      |---------------------------------------------------|
      |  struct Post {                                    |
      |    uint256 id;                                    |
      |    address author;                                |
      |    string title;       (1 - 100 bytes validated)  |
      |    string description; (1 - 500 bytes validated)  |
      |    uint64 createdAt;   (block.timestamp)          |
      |    uint256 likes;                                 |
      |    uint256 dislikes;                              |
      |    uint256 totalTips;                             |
      |  }                                                |
      |                                                   |
      |  ReentrancyGuard (OpenZeppelin 5.x)               |
      |  Checks-Effects-Interactions                      |
      |  Paginated View: getPosts(offset, limit)          |
      |  No receive() / No fallback() (Never holds BOT)   |
      +---------------------------------------------------+
                 ^
                 | like(id) / dislike(id) / removeVote(id)
                 |
          [ Voter / User ]

Key Technical Specifications:
- Framework: Foundry (Solidity ^0.8.24)
- Security: OpenZeppelin ReentrancyGuard on all state-mutating functions
- Custom Errors: Gas-optimized errors (InvalidTitleLength, AlreadyVoted, etc.)
- Invariant Fuzz Testing: 256 fuzz runs with 15 random voting sequences per run;
  guarantees likes and dislikes strictly equal recorded voter mappings and never underflow.
- Comprehensive Unit Tests: 23 passing tests covering boundaries, reentrancy attacks,
  rejecting authors, and pagination edge cases.
